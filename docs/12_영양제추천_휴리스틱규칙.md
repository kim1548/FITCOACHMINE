# 12. 영양제 추천 — 휴리스틱 규칙 설계 (D1 확정안)

> 설계서(11) §3①의 "섭취량 집계" 한계를 해결하는 구체안.
> `diet_logs`엔 미량영양소가 없으므로, **사용자 프로필·목표·생활습관 신호**로 부족 영양소를 추정한다.
> ML 아님 — **가중치 규칙 테이블**의 합산.

---

## 0. 동작 원리 한 줄 요약

```
여러 신호(성별·나이·목표·생활습관·흡연·임신·식단) 각각이
→ 특정 영양소에 "부족 점수"를 가산
→ 영양소별 점수 합산 → 상위 영양소 = 부족 추정
→ 그 성분을 가진 영양제 추천 (설계서 §3③~⑤로 연결)
```

`diet_logs`의 **단백질**만은 실제 계산 가능 → 유일하게 데이터 기반(나머지는 휴리스틱).

---

## 1. 입력 신호 (전부 기존 필드 + user_health_profile)

| 신호 | 출처 컬럼 | 값 예시 |
|---|---|---|
| 성별 | `users.gender` | 남 / 여 |
| 나이 | `users.age` | 25 |
| 목표 | `users.goal` | 체중감소 / 유지 / 벌크업 |
| 생활패턴 | `users.lifestyle` | 학생 / 일반사무직 … |
| 운동빈도 | `users.workout_frequency` | 주1회 … 주5회 |
| 흡연 | `user_health_profile.is_smoker` | T/F |
| 임신·수유 | `user_health_profile.is_pregnant` | T/F |
| 단백질 섭취 | `diet_logs.protein` (7일 평균) | g/일 (**실제 계산**) |

---

## 2. 대상 영양소 (MVP 12종)

`VIT_D`(비타민D) · `OMEGA3`(오메가3) · `CALCIUM`(칼슘) · `MAGNESIUM`(마그네슘)
`IRON`(철분) · `ZINC`(아연) · `VIT_C`(비타민C) · `VIT_B`(비타민B군)
`PROTEIN`(단백질) · `PROBIOTICS`(유산균) · `LUTEIN`(루테인) · `FOLATE`(엽산)

---

## 3. 가중치 규칙 테이블 (핵심)

> 가중치: **3=강 / 2=중 / 1=약**. 한 신호가 여러 영양소에 점수를 줄 수 있다.

### 3-1. 성별 `gender`
| 조건 | 영양소 | 가중치 | 근거 |
|---|---|---|---|
| 여 | IRON | 3 | 월경으로 철분 손실 |
| 여 | CALCIUM | 2 | 골밀도 |
| 남 | ZINC | 2 | 남성 생리·근합성 |

### 3-2. 나이 `age`
| 조건 | 영양소 | 가중치 | 근거 |
|---|---|---|---|
| ≥ 40 | VIT_D | 2 | 합성능 저하 |
| ≥ 40 | CALCIUM | 2 | 골손실 |
| ≥ 40 | LUTEIN | 2 | 눈 노화 |
| ≤ 29 | VIT_B | 1 | 활동·피로 |

### 3-3. 목표 `goal`
| 조건 | 영양소 | 가중치 | 근거 |
|---|---|---|---|
| 체중감소 | VIT_B | 2 | 에너지 대사 |
| 체중감소 | OMEGA3 | 2 | 식이지방 보완 |
| 체중감소 | VIT_D | 1 | 결식 시 부족 |
| 벌크업 | PROTEIN | 3 | 근합성 |
| 벌크업 | ZINC | 2 | 테스토스테론·회복 |
| 벌크업 | MAGNESIUM | 2 | 근수축·회복 |
| 유지 | OMEGA3 | 1 | 기본 건강 |

### 3-4. 생활패턴 `lifestyle`
| 조건 | 영양소 | 가중치 | 근거 |
|---|---|---|---|
| 일반사무직(실내) | VIT_D | 3 | 햇빛 노출 부족 |
| 일반사무직(실내) | LUTEIN | 2 | 모니터·블루라이트 |
| 일반사무직(실내) | MAGNESIUM | 1 | 스트레스 |
| 학생 | VIT_B | 2 | 집중·피로 |
| 학생 | MAGNESIUM | 1 | 스트레스 |

### 3-5. 운동빈도 `workout_frequency`
| 조건 | 영양소 | 가중치 | 근거 |
|---|---|---|---|
| 주4회 이상 | PROTEIN | 2 | 회복 수요 |
| 주4회 이상 | MAGNESIUM | 2 | 근경련 예방 |
| 주4회 이상 | VIT_C | 1 | 운동 산화스트레스 |
| 주1~2회 | (가산 없음/종합비타민 폴백) | - | - |

### 3-6. 흡연 `is_smoker = T`
| 영양소 | 가중치 | 근거 |
|---|---|---|
| VIT_C | 3 | 흡연 시 소모 급증 |
| OMEGA3 | 1 | 심혈관 보조 |

### 3-7. 임신·수유 `is_pregnant = T`
| 영양소 | 가중치 | 근거 |
|---|---|---|
| FOLATE | 3 | 태아 신경관 |
| IRON | 3 | 혈액량 증가 |
| CALCIUM | 2 | 태아 골형성 |
> ⚠️ 임신은 금기 성분도 많음 → **안전 필터(설계서 §3④) 우선 적용**. 임신 시 일부 영양제는 추천에서 제외.

### 3-8. 단백질 — **유일한 실데이터 규칙** `diet_logs.protein`
```
목표섭취 = 체중(kg) × 계수      # 유지 1.0 / 체중감소 1.2 / 벌크업 1.6
부족분   = 목표섭취 − 7일평균섭취
if 부족분 > 0:  PROTEIN += clamp( 부족분 / 목표섭취 × 3, 1, 3 )   # 부족 비율로 1~3점
```
> 다른 영양소는 추정이지만, 단백질은 **"실제 식단 기록 기반"** 이라 발표에서 강조 포인트.

## 4. 점수 합산 → 추천 변환

```
1) nutrient_score[code] = Σ (해당하는 모든 규칙의 가중치)
2) 상위 영양소 선정: score ≥ 임계값(기본 3) 인 것만 "부족 추정"으로 채택
3) 채택 영양소 → supplement_ingredient 역인덱스 → 영양제 후보 (설계서 §3③)
4) 안전 필터 (§3④) → 금기 제외 / 주의 경고
5) 영양제 점수 = Σ (커버하는 부족영양소 score × 함량커버리지)  → 0~100 정규화
6) Top 5 → Gemma 추천 이유 (§5)
```

### 예시 (가상 사용자)
> 28세 / 여 / 사무직 / 목표=체중감소 / 주3회 / 비흡연

| 영양소 | 가산 내역 | 합계 |
|---|---|---|
| VIT_D | 사무직3 + 체중감소1 | **4** ✅ |
| IRON | 여3 | **3** ✅ |
| VIT_B | 체중감소2 + (29↓)1 | **3** ✅ |
| OMEGA3 | 체중감소2 | 2 |
| LUTEIN | 사무직2 | 2 |
| CALCIUM | 여2 | 2 |

→ **부족 추정: 비타민D · 철분 · 비타민B** → 이 성분 가진 영양제 추천 + 레이더 차트에 표시.

---

## 5. 레이더 차트 매핑 (프론트)

- 축 = 영양소 12종, 값 = `nutrient_score`를 0~100 스케일로 변환.
- 점수 높을수록(부족할수록) 축이 안쪽으로 들어간 형태 → "부족한 영역" 시각화.
- 추천 카드의 경고배지 = 안전 필터 결과(`주의` 메시지).

---

## 6. 데이터화 방식

- 위 규칙 테이블은 **코드 상수(dict) 또는 `recommendation_rule` 테이블**로 관리.
  - 권장: **Python 상수 모듈**(`app/services/supplement_rules.py`)로 시작 → 수정·발표 설명 쉬움.
  - 규칙을 DB 테이블로 빼면 관리자 화면에서 수정 가능하나 MVP엔 과함.
- 영양소-영양제 매칭은 `supplement_ingredient`(설계서 §2-1) 사용.
